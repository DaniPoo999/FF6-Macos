# Source provenance

The optional CRT presentation is independently implemented from the fixed-preset
beam/scanline/aperture-grille equations studied in **Sony Megatron Colour Video
Monitor v2**, by **Major Pain The Cactus**, distributed in libretro/slang-shaders.
The inspected local files and SHA-256 hashes are recorded in
`config/crt_provenance.json`; adaptations and evidence boundaries are in
`docs/CRT.md`. No Slang source, compiler, reference tables, RetroArch component,
or Microsoft HDR helper is included in the product. The native implementation
uses its own polynomial integration, standard sRGB transfer functions and
Apple's EDR output contract. This attribution does not assert a blanket license
for the heterogeneous reference shader collection.

The read-only reference project attributes its disassembly and adaptations to
everything8215/ff6 under GPL-3.0. This project retains that attribution for
derived reverse-engineering knowledge and format implementations. Upstream pin:
813013276c952fdd27edcf7b8b86f17291542cbf.

SDL3 uses the zlib license; any distribution bundling SDL must include its
license. Emulator projects are development references only and are not linked
into or included with production artifacts. No original game assets are
licensed by these source notices; all content is extracted locally from the
user's ROM. See docs/RESEARCH.md for source links and pinned inspections.

The raster implementation is independently structured from explicit component
equations and semantic layer contracts. Mesen 2.1.1 is the development oracle;
its source informed test-adapter addressing and the pinned output profile. Ares
at the pin below supplies an independent color-math/display comparison. No PPU
core code is copied or linked. See docs/RASTER.md for sources and limitations.

The private sample test dynamically compiles the unmodified
`DspVoice::DecodeBrrSample` method from Mesen 2.1.1 (Sour and contributors,
GPL-3.0), after checking its source hash. The method, generated test executable
and Mesen LICENSE remain together under ignored development evidence. The
tracked wrapper supplies only bounded block reads and captures the decoded
values; no Mesen source or emulator component enters a production target or
application. Sources/pins and the comparison boundary are in docs/SAMPLES.md
and config/sample_provenance.json.

The fixed-delay mixer comparison compiles only pinned Mesen volume/FIR/echo
methods and cadence/noise logic into ignored evidence. It also compiles the
unmodified `SPC_DSP::echo_output` function from Snes9x's blargg library (Shay Green,
LGPL-2.1-or-later) to resolve a documented signed-volume discrepancy. The generated
file retains its original copyright notice, with the complete LGPL beside it.
No reference source or test executable enters production. See docs/MIXER.md and
config/mixer_provenance.json for hashes and the precise comparison boundary.

The isolated voice test similarly inserts pinned, unmodified Mesen envelope,
voice, interpolation and cadence methods into a private wrapper. It observes
mono output after effective sample events, without compiling the emulator or
shipping any of those methods. Its source/license files and executable remain
under ignored evidence. See docs/VOICE.md and config/voice_provenance.json.

The original-game audio capture builds the complete external Mesen 2.1.1 core
(Sour and contributors, GPL-3.0) in ignored research storage. Observation hooks
record original values without changing its arithmetic. Its source and complete
license remain there; the separately built host SDL2 dependency retains its
zlib notice. Neither core, observer nor SDL2 is linked into production. See
docs/AUDIO_CAPTURE.md and config/audio_capture_provenance.json.

The fixed Gaussian interpolation kernel is generated by an adaptation of Ares's
analytic construction in `ares/sfc/dsp/gaussian.cpp` at the pin below. The 512
integers describe the interpolation filter, not original game content. The
generator and generated kernel retain this ISC notice through this file, which
is included with the builder and generated application. Native envelope and
voice implementations use semantic sample state, a contiguous lookahead queue
and sample-time phase residues; no device model or scheduler is copied.
